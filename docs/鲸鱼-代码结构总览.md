## 一、技术栈与规模

- Kotlin + Compose Multiplatform（Material 3），**三模块**：`app/`（Android 薄壳）＋ `shared/`（KMP，全部代码）＋ `desktopApp/`（Windows 入口与打包）；无后端、无数据库、无 Flow/LiveData。
- 源码**全在 `shared/src/`**：共 **91 个 `.kt`，约 42.3k 行**（`jvmSharedMain` 59 个 / 33.5k 行是主体，`commonMain` 12 / 3.9k，`androidMain` 11 / 2.1k，`jvmMain` 9 / 2.8k）。
  `app/src/main` **已无任何 `.kt`**（只剩 manifest 与资源）——老文档里"源码在 `app/src/main/java/com/mysticat/roleplay/`"的说法已作废。
- 存储：全部是本地 JSON + 文件（`kotlinx.serialization`），Key 走 Android Keystore（桌面走 Windows DPAPI）。
- 网络：`OkHttp`（自建，不引 SDK），走 OpenAI 兼容的 `/chat/completions` 与 `/images/generations`；**下载类请求统一经 `RemoteFetch`**（镜像优先＋原始兜底，第 54 轮）。
- 单 Activity + Compose Navigation；纯本地 BYOK，App 只与"用户自己填的供应商"通信。

├── commonMain/        纯 Kotlin（看不见 java.io/OkHttp）：Models / ProviderProfiles / ModelCatalog / NarrativeStyles / ThinkingFilter / Account / CustomTemplate / UserSetting / CharacterVoices / EngineSpec / OutputFormats / WorldBook
├── jvmSharedMain/     ★ 双端共用的全部 UI 与 JVM 数据层（被 UI 引用的类型必须住在这里或更低）

│   ├── ui/    17 个文件  ← MainScreen / Common / ImageTools / CardExport / ChatBackgrounds / Changelogs / VoiceKit / WorldBookUi / WhaleIcons / Platform ＋ 桌面外壳（DesktopShell / DesktopLayout / DesktopFeatures / DesktopShortcuts / DesktopDragDrop / DesktopOnboarding / DesktopAppBridges）

> 这与"是否只有 JVM target"无关：`commonMain` 看不到 `java.io.File`/OkHttp，所以 UI 不进 `commonMain`。

## 二、顶层与入口（`shared/src/androidMain/.../` 5 个 + `jvmSharedMain/AppRoot.kt`）

| 文件 | 职责 |
|---|---|

## 五、三条关键数据流

**1）一次对话（最重要，改需求必看）**

```
输入栏 → ChatViewModel.send()
   ├ 追加 user 消息（含图片附件）→ persist() 落盘 + 同步内存态 + 刷新列表
   └ requestReply(history)
        ├ 锁定 targetId（流式期间用户可能切走，完成时必须按 id 写回）
        ├ 重取 conv / character / settings（**风格等会话级参数在这里读取，所以改动即时生效**）
        ├ maybeUpdateSummary()  溢出消息后台合并为前情提要（非阻塞）
        └ AiClient.chatStream()
             ├ messages[0] = buildSystemPrompt(人设/世界观/用户设定/摘要/记忆/styleHint/补充要求)
             ├ messages[1..] = trimHistory(history, historyLimit)
             └ 流式 delta → appendRecv() → 打字机按 16ms/拍揭示到界面
   → 完成后 updateConversation(targetId) 按 id 覆盖写回（含 500 字一次的静默检查点）
```

要点：**系统提示词每轮重新组装**，没有任何缓存；异步任务完成时**一律按 id 回取会话**（`updateConversation`），绝不写"当前看起来是当前"的那个会话。

**2）设置链路**：`ProfileScreen` / `MainScreen` → `SettingsScreen`（`SettingsViewModel` 编辑态 + `isDirty`）→ `save()` → `Repository.saveSettings()`（Key 加密、更新内存缓存）。

**3）存储链路**：一切读写都经 `Repository`；写入恒为"临时文件 + rename"原子替换；账号切换只改 `current_account.txt`，数据目录随之切换。

## 六、改代码前必须知道的约定

1. **写入必须原子且临时名唯一**——并发写同一会话文件是真实可达的（流式 IO 线程 vs 主线程改风格）。
2. **异步完成的任务按 id 回写**，不要用"当前会话"（会串会话、会覆盖期间的回复）。
3. **会话 id 哨兵**：`new` = 恢复最近会话，`blank` = 强制空会话。
4. **加一个供应商能力要改两处**：`ProviderProfiles`（能力与参数形态）+ `ModelCatalog`（模型清单）。
5. **Key 是一家一份**（`providerKeys`，key = 内置关键词 / 自定义供应商 id）；`chatApiKey` / `imageApiKey` / `imageProviderKeys` 都只是**读老数据的兼容通道**，解析顺序在 `Repository.loadSettings()` 里，不能反。
6. **版本号两条线分开，且都已集中在 `gradle/libs.versions.toml`**：Android 是 `androidVersionName/Code`（`versionCode` 全局递增，`app/build.gradle.kts` 只是读它）；桌面是 `desktopVersionName/Code`（`desktopVersionCode` 每次发版必 +1）。发版 tag 同样分开：Android `v<版本>` / 桌面 `win-v<桌面版本>`，互不覆盖。
7. **再加一个"存图片路径的字段"必须同步两处**，漏一处就丢图或断链：① `Repository.referencedImagePaths()`（图片回收按引用清理，漏了会被当垃圾删掉）；② `Backup` 的导出与导入 remap。`backgroundUriDesktop` 就是这么加的（第 35 轮）。
8. 思考类模型的输出预算由 `effectiveMaxTokens` 决定（思考时会抬到 8192），别在调用处自己写死。
9. **叙事风格加轴/改文案只动 `data/NarrativeStyles.kt`**（UI 与 prompt 都遍历 `AXES`）；风格只有一个写入口 `ChatViewModel.applyNarrative`，任何界面都不许自己存一份风格状态。多选轴的档位顺序 = 选择顺序，`buildHint` 依赖这个顺序（"以最后选中的为准"）。
10. **IO 协程里不能直接写 Compose `mutableStateOf`**：会启动即崩 `IllegalStateException`（snapshot 状态被跨线程改）。做法是 `withContext(IO)` 里读、回主线程再赋值。
11. **在一个 Composable 前面插新组件时，别把它上面的 `@OptIn` 注解隔开**——注解和被标注的函数分开后，ModalBottomSheet 一类实验 API 会报 experimental 编译错误。
12. **Kotlin 属性必须在 `init` 赋值之前声明**（属性声明顺序＝初始化顺序，声明在 `init` 之后就还没初始化）。
13. **下载/联网抓取一律走 `RemoteFetch`**，别自己 new `OkHttpClient`——本机对 github.com 有 TLS 中间拦截，散写会把"证书问题"误报成"网络错误"（第 54 轮的教训）。
